# v1.3.0 — Write actions, proving in the browser, and the missed-round penalty

The UI could read the whole protocol and write to almost none of it. v1.3 adds governance voting and
execution, generates zk proofs in the user's own browser, and closes the last Medium finding from the
v1.0 review: oracle nodes that never submit are now penalised.

As before: read the second section before the first.

---

## What v1.3 adds

**Governance write actions.** Vote For, Against, or Abstain; queue a succeeded proposal; execute a
queued one. Each is disabled with its actual reason rather than offered into a transaction that
reverts. A holder who never delegated, one who delegated after a proposal's snapshot, and one whose
tokens vote through someone else all hit the same revert on chain, and the UI tells each which case
they are in.

**Private actions, proved in the browser.** A deposit's secret is entered in the page, the commitment
tree is rebuilt locally, the proof is generated in the browser, and the connected account submits it.
The secret never reaches a request: the tree is fetched by page, and the deposit is located locally,
because asking the API which leaf holds it would name the deposit about to be spent. Proving takes
around twenty seconds, and the UI says so before it starts.

**Missed-round slashing (ORC-1).** A node that stays silent in a round that ran to its deadline loses
0.5% of its stake; a third consecutive miss costs 10% instead, and the count starts again. Excused: a
round nobody submitted to, a round settled before its deadline, and a removal by an admin or for low
stake before the deadline. Requesting to unstake is not an excuse. Misses are judged strictly in
round order, so a streak is never computed with a round missing.

## What v1.3 does not change

Everything the earlier release notes say the protocol is not, it still is not:

- **No external audit.** The v1.0 internal review is the authors reviewing their own work.
- **No deployment, anywhere.** Infrastructure is defined and validated, and has never been applied.
- **No mainnet, no funds, no custody.**
- **No proposal creation in the UI.** A proposal carries arbitrary calldata, and a UI for it is a
  calldata builder — its own design problem.
- **No oracle staking or registration in the UI.** Operator tooling that moves real stake.

## Breaking changes

**Two oracle events changed signature.** `NodeReactivated` and `NodeDeactivated` now carry
`nodeSetVersion`. Their topic hashes change, so anything decoding them by the old signature stops
matching. The field is what lets a node's silence be judged at all: a round freezes its eligible set as
a version when it opens, and the contract's `isEligibleAt` reads current state, so once a node left
nothing could say which rounds had expected to hear from it. Storage layout is unchanged; applying
this to a deployed system is a UUPS upgrade.

**Two migrations.** `000009` records each node's active intervals. `000010` records per-round outcomes,
adds a judgement marker to rounds, and **drops `oracle_nodes.missed_rounds`** — the count is now read
from the recorded outcomes.

**zk proving deviates from `docs/zk.md`.** The spec routes private inputs to the Rust proof service.
v1.3 proves in the browser, because the circuit derives both a user's commitment and their nullifier
from one secret, and a hosted prover would receive exactly the link between a deposit and its spend
that the schema refuses to store. The Rust service is kept as the reference the browser path is
checked against, not as a prover users send secrets to. Recorded in `DEFERRED.md`.

## Defects found while building v1.3

Some surfaced by running the system against a browser or a real chain, and some by reading code before
building on it. None had been caught by the tests that existed.

| Defect | How it surfaced |
|---|---|
| The v1.1 Nodes page said missed rounds were "recorded but not penalised". Nothing ever recorded them: every count was zero. | Reading who writes the column, while planning ORC-1 |
| Vault deposits and withdrawals showed a green hash on *submission*, and nothing read the receipt. A transaction that reverted on chain displayed as one that landed — including one reverted by v1.2's own slippage bound. | Building governance writes on the same transaction component |
| Execute was offered two days before the timelock would accept it. The executable time came from the indexer, which had not caught up, and the check skipped itself when the time was missing. | A proposal taken through queue and execute against a time-warped local chain |
| Missed-round judgement would have slashed nodes for rounds they submitted to, whenever a round had more than 64 submissions. | Reading the submission listing before wiring the judgement to it |
| Rounds settle out of round order across feeds, so a streak could have been judged with a round missing and a slash decided that could not be withdrawn. | The same |
| The compiled circuit served to browsers carried absolute paths from the development machine. | Inspecting the artifact before committing it |
| The browser-proof check passed on the development machine and failed twice on a clean runner, because `circomlibjs` and then `forge` were installed only locally. | CI |

## Checked against a real chain

- A vote cast through the UI landed, and was indexed with the full delegated weight.
- Execute enabled only when **chain** time allowed it: with the chain ten days ahead of the browser's
  clock, the button enabled while the browser's own clock still said not yet.
- A proof generated inside a web page was accepted by the on-chain verifier. The nullifier it spent
  matched one derived independently in a separate process.
- A node silent through three rounds lost exactly 0.5%, 0.5% of the reduced stake, and 10%; nodes that
  submitted lost nothing. Each excused case was put on chain, and none slashed anyone.

**Not observed live:** a reverted transaction's display changing from *pending* to *reverted*. The
browser pane used for verification was hidden, which pauses the page's polling. It displayed as
pending rather than confirmed, which is the defect that was fixed; the transition itself is covered by
unit tests.

## Verification

348 contract tests, 21 circuit tests, 26 zk service tests, 112 frontend tests, 41 end-to-end tests, 15
backend packages. Slither clean. Storage layouts unchanged from their baselines.

Drift checks: the contract ABIs against `forge`; the frontend's hand-written ABIs against those,
comparing struct fields rather than the word "tuple"; the frontend's API types against the Go structs;
the Poseidon artifact and the verifier against fresh generation; the browser's circuit artifact against
a fresh compile; and the browser's proving packages against the pinned toolchain. The checks added in
this release, and the contract ABI check, were each confirmed to fail when the thing they guard was
deliberately broken.

## Accepted risks

Eleven entries in `DEFERRED.md`. ORC-1 has moved to the decided table. One is new: the outlier check
sees at most 64 submissions per round, which errs toward missed penalties rather than wrongful ones.
