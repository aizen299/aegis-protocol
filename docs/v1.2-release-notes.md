# v1.2.0 — Slippage bounds on the vault

A small release with a **breaking interface change**, tagged on its own so the break is easy to find.

---

## Breaking

`deposit` and `withdraw` take an extra argument:

```solidity
deposit(uint256 assets, address receiver, uint256 minShares)
withdraw(uint256 shares, address receiver, uint256 minAssets)
```

Both revert with `SlippageExceeded(got, wanted)` when the fill is below the caller's floor, checked
before any state is written — a rejected call credits no shares, moves no totals, and returns the
caller's assets.

Any integrator calling the two-argument form must add the third. There is no deprecation window and
no overload, deliberately: an overload leaves the unguarded path callable by anyone who does not
know to avoid it, which is the defect rather than a migration aid. Nothing is deployed and no value
is at stake, so this is the cheapest the change will ever be.

## Why

VLT-1, from the v1.0 internal review. `docs/solidity.md`'s vulnerability table requires slippage
parameters where needed, and neither entry point had one. Share price moves with the strategy's
reported holdings, so a withdrawal landing after a loss filled at the worse rate with no recourse —
no revert, just less money, because the caller had no way to express a floor.

## Zero still means no bound

`minShares == 0` and `minAssets == 0` are permitted and mean exactly that.

Requiring a non-zero value was considered and rejected as ceremony: a caller who wants no bound
passes `1` and satisfies it trivially, leaving a check that constrains nothing while implying it
constrains something. This project has already had to remove two of those — ORC-1's dead slash
constants and the zk circuit's tautological `assert(s * s == s * s)`.

What the change buys is that the parameter *exists*, so every caller makes a decision. The typed
frontend ABI proved the point immediately: both call sites failed to compile until they passed one.

## What v1.2 does not change

Everything `docs/v1.0-release-notes.md` and `docs/v1.1-release-notes.md` say the protocol is not, it
still is not: no external audit, no deployment anywhere, no mainnet, no custody of value, and no
write actions in the UI beyond the vault forms that already existed.

## Verification

344 contract tests, 21 circuit, 26 zk service, 56 frontend, 39 end-to-end. Slither clean. Storage
layout unchanged — no state variable was added, removed, or reordered.

The ABI drift check was confirmed to **fail before** the ABI was regenerated, so its catch is
demonstrated rather than assumed. Mutations: removing both bounds fails 8 contract tests; rounding
the floor up instead of down fails a frontend test, because a floor above the quoted rate would
revert a fill at exactly the expected price.

The UI shows the floor rather than hiding it: *"Reverts below 99.5 tUSD, a 0.5% tolerance on the
current rate."*
