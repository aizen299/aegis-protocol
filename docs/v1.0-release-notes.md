# v1.0.0 — Production Release

Aegis Protocol v1.0. A modular DeFi protocol on Arbitrum: a vault engine, an oracle network with
staking and slashing, DAO governance behind a timelock, and a zk privacy gate.

Read the second section before the first.

---

## What v1.0 is

**Production-ready, never deployed.** Every layer is built, tested, and hardened to the standard the
spec sets. Nothing has been applied to a cloud account, no contract is on a public chain, and no
value has ever been at risk.

Added in this release:

- **Observability.** Indexer lag in seconds and blocks, API latency and error counts, emitted
  through CloudWatch's Embedded Metric Format — no SDK, no credentials in the task, no
  `PutMetricData` on a request path. Eight CloudWatch alarms, with a build-time check that every
  alarm names a metric some service actually publishes and pins a `Service` dimension a real service
  sets.
- **Load profiles.** An open-loop harness that measures against an absolute schedule rather than
  sleeping between requests, so a slow service cannot quietly reduce the offered rate. Baselines
  below.
- **The secret path, exercised.** The staging SSM path runs against a real Parameter Store
  implementation in CI: real SDK, real `GetParameter`, real SecureString decryption.
- **Role migration, performed.** `VAULT_MANAGER_ROLE` migrated from the admin key to the timelock
  through all three reversible stages, with a recorded transcript.
- **An internal audit simulation.** Seven findings across four modules. One fixed, six accepted with
  triggers.

Fixed in this release:

- **Governance proposal threshold could be met with borrowed weight.** `propose` read voting power
  as it stood during the call, so an attacker could flash-borrow tokens, delegate, propose, and
  return them in one transaction. It now reads power one tick back. Voting itself was never exposed.
- **Both ECS task definitions omitted `APP_ENV`**, which is required with no default. Both services
  would have crash-looped on their first deploy. Generalised into a check that every task definition
  provides the variables its service marks required.
- **An ambient `AWS_ENDPOINT_URL` could redirect secret reads silently.** The SSM client resolves
  that variable at construction, so a staging task could have read its slasher key from any endpoint
  and still logged `provider=aws-ssm`. Startup now fails on an ambient override.

## What v1.0 is not

Stated plainly because each of these is something a reader could otherwise assume.

- **No external audit.** The internal audit simulation in `docs/v1.0-audit-simulation.md` is the
  authors reviewing their own work. It finds the defects the authors are capable of seeing. It is
  not a substitute for an audit and must not be cited as one.
- **No deployment, anywhere.** `docs/project-spec.md` §5 lists an AWS staging deployment for v1.0
  and §7 names Arbitrum Sepolia. Neither happened: no AWS account exists for this project.
  Infrastructure is defined in Terraform, validated, and preflight-checked, and has never been
  applied. Whether it applies at all is unproven — `terraform validate` checks syntax and types, not
  quotas, IAM propagation, or subnet and AZ mismatches. **This is a deviation from a locked spec.**
- **No mainnet, no funds, no custody.** No contract holds value belonging to anyone.
- **No proven task-role access to SSM.** The secret path is proven against LocalStack, which
  exercises the SDK and the protocol but not the authorization.
- **The role migration ran on a local chain, one role, three stages.** Not staging, not a real
  multisig, not the full role sequence, and not stage 4 — which is the irreversible one.
- **No staging load baseline.** Every number below was measured locally. The indexer-lag alarm
  threshold stays provisional at 300s and says so at the resource.
- **A known unfixed High-severity finding.** See below.

## The finding you should know about before using anything here

**A zk proof is a bearer instrument.** Nothing binds a proof to the account submitting it — not the
circuit's public inputs, not the gate. Anyone who sees a proof in the mempool can copy the calldata
and land it first, permanently burning the honest user's nullifier. Their deposit is safe; their
ability to act on it is destroyed, by anyone willing to pay more gas.

It is accepted for v1.0 only because the gate currently confers no benefit: it marks a nullifier
spent and emits an event that nothing consumes. `test_aStrangerCanSubmitSomeoneElsesProof` is left
passing as the record of it.

**No contract may consume `PrivateActionExecuted` or gate on `isSpent` until a submitter binding
exists.** At that moment the frontrunner receives whatever the gate confers, and this stops being
griefing and becomes theft.

## Measured

Locally, against Anvil and Postgres in Docker. Lower bounds, not service levels.

| Profile | Offered | Result |
|---|---|---|
| Read | 200 req/s for 20s over two endpoints | p50 1.14ms, p95 1.85ms, **p99 2.51ms**, no errors, no schedule slip |
| Ingest | 400 commitments across 400 blocks | indexed in **1.58s**, ~250 events/s, leaf indices contiguous |

The ingest profile did not saturate the indexer: producing the events took 2m19s while indexing them
took 1.58s, so the chain was the bottleneck. What it proves is that a dense range indexes completely,
with contiguous and unduplicated leaf indices.

## Verification

337 contract tests, 19 circuit tests, 25 zk service tests, 38 end-to-end tests, 15 backend packages.
Slither clean. Fuzz and invariant suites on the vault, oracle, governance, and zk modules. Committed
storage-layout baselines checked against every contract before any upgrade, and drift checks on
every generated artifact — ABIs, the Poseidon contract, the verifier, and the proof fixture.

## Accepted risks

Seven entries in `DEFERRED.md`, each with a trigger that can actually fire. The ones worth reading
first: the bearer-proof finding above, the absent penalty for an oracle node that never submits, and
the missing slippage bound on vault deposits and withdrawals.
