# v1.3 — Penalising oracle nodes that do not submit (ORC-1)

Closes ORC-1, from the v1.0 internal review and recorded in `DEFERRED.md`. `docs/oracle.md` lists four
slashable conditions; two are implemented. A node that stakes and never submits raises a round's
quorum denominator without raising its numerator, and pays nothing for it.

**This reopens v0.2, including a contract change.** Sections 2.1 and 2.2 are the decisions that need
sign-off before any code.

---

## 1. What reading the code found first

**Missed rounds are not recorded, let alone penalised.** `oracle_nodes.missed_rounds` exists, the API
serves it, and the v1.1 Nodes page displays it — but nothing writes it. It defaults to zero and stays
there. The page's own disclosure, *"Missed rounds are recorded but not penalised"*, is false in its
first half. The component test did not catch it because it mocked a count of twelve, and the live
check did not either, because it only ever saw an empty node list.

That label was written specifically to avoid implying something untrue about enforcement. It implies
something untrue about recording instead. This plan fixes it in passing, since detecting a miss is
exactly what populates the column.

**The eligible set for a past round cannot be reconstructed off chain.** To call a node's silence a
miss, the aggregator needs to know which nodes were expected to submit to that round. The contract
freezes that set at `openRound` as a node-set version. But no event carries the version:
`NodeRegistered`, `NodeDeactivated`, and `NodeReactivated` say *that* a node entered or left the set,
not *at which version*. And `isEligibleAt` reads current state — `node.active` now — so asking the
chain after the fact answers a different question.

**A node deactivated after a round opens cannot submit to it, but stays in its denominator.** This is
deliberate and already tested (`test_deactivatedNodeCannotSubmit`,
`test_deactivatingMidRoundDoesNotShrinkQuorum`): freezing the denominator stops nodes leaving
mid-round to shrink the quorum they must clear. It matters here because it cuts both ways — see §2.2.

## 2. Decisions

### 2.1 Staking events carry the node-set version

`NodeReactivated` and `NodeDeactivated` gain a `nodeSetVersion` field: the version at which the node
entered or left the active set.

*Changed from the approved plan, which named three events.* `_activate` emits `NodeReactivated` on
every activation, including first registration — `register` calls it before emitting
`NodeRegistered`. Every interval boundary is therefore already marked by exactly one of the two
events, and adding the version to `NodeRegistered` would repeat a value emitted in the same
transaction while changing a third event signature for nothing. The indexer records each node's active intervals,
and a node was eligible for a round when the round's frozen version falls inside one.

**Alternatives considered:**

- *Snapshot the eligible node list on chain at `openRound`.* Exact, but writes up to `maxNodes`
  addresses per round — storage growing with the node set on every round, forever, to answer a
  question the backend can answer from events.
- *Call `isEligibleAt` from the aggregator.* Wrong: it reads current `active`, so a node that has since
  deactivated reads as never eligible, and its miss disappears.

This is an **event signature change**. It moves the committed ABI and needs an indexer migration.
Storage layout is untouched — the version is already tracked in state; it was just never emitted.
Nothing is deployed, so there is no history to backfill; the upgrade path is recorded for completeness
in §5.

### 2.2 Which silences are slashable

A node eligible for a round that did not submit is a candidate miss. Three exclusions:

| Case | Slashed? | Why |
|---|---|---|
| The round received **no submissions at all** | No | Every node silent at once is an outage — a data source down, an RPC partition — not an attack. Slashing the whole set for infrastructure failure punishes honest operators for the thing they could least control. |
| Deactivated after open with reason `UNSTAKE_REQUESTED` | **Yes** | The node chose to leave a round it was counted in. Exempting this would be the escape hatch: sit in the eligible set, unstake after open, never submit, never pay. |
| Deactivated with reason `MANUAL` or `BELOW_STAKE_FLOOR` **before the round's deadline** | No | The node was removed, and then blocked from submitting. Slashing it for a silence it was prevented from breaking is unjust. |
| Deactivated with those reasons **after the round's deadline** | **Yes** | Nothing blocked it. It was silent while it could still have submitted. |

*Refined after approval.* Eligibility is a version interval, and a version is not a time: a node
removed for low stake a week after a round closed still satisfies *activated ≤ v < deactivated*. As
first written, the exemption would have excused that node for a silence nothing forced on it. The
exemption now requires the removal to have happened within the round's submission window, so each
interval records when the node left, not just at which version.

**The zero-submission exclusion has a cost, stated plainly:** an adversary who can make *every* node
silent — by attacking a shared data source, say — halts a feed without penalty. That is an attack on
infrastructure rather than on the staking design, and it is not something missed-round slashing could
price anyway: it would slash the honest nodes alongside.

### 2.3 Consecutive misses

`docs/oracle.md` specifies a 10% penalty for "N consecutive misses" and leaves N undefined.

- **N = 3.**
- **Counted per node, across every round the node was eligible for**, in the order rounds opened.
  Stake is held per node, not per feed, so a node silent on three feeds' rounds in a row is the same
  failure as one silent on three rounds of one feed.
- **A submission resets the streak.** So does an excluded round from §2.2, which is neither a miss nor
  a submission — it does not extend a streak and does not break one.

### 2.4 One penalty per node per round

The contract already enforces `_slashedInRound[roundId][node]`: one slash per node per round. So on the
round that completes a streak of three, the 10% consecutive penalty **replaces** the 0.5% single-miss
penalty for that round rather than being added to it. The streak then restarts from zero.

Without the restart, a node that stays down is drained 10% on every subsequent round. With it, the
cost is 10% per three consecutive misses — and a node whose stake falls below the floor is deactivated
automatically, which ends the sequence.

10% is exactly the contract's per-slash cap (`maxSlashBps`). The consecutive penalty is sized at the
cap, not beyond it.

### 2.5 The Nodes page tells the truth

`missed_rounds` is populated with slashable misses. The page's disclosure is corrected to describe what
is now true, and the component test stops mocking a value nothing in the system could produce.

## 3. Invariants

- A node is judged only for rounds whose frozen version falls inside one of its active intervals.
- A round with no submissions slashes no one.
- A node removed by `MANUAL` or `BELOW_STAKE_FLOOR` before a round's deadline is never slashed for
  missing it. Removed after the deadline, it was free to submit and is judged like any other.
- No node receives more than one penalty per round, and none exceeds `maxSlashBps`.
- A slash decision is written to Postgres before it is executed, as the existing penalties are, so a
  crash between decision and execution retries rather than double-slashes.
- `missed_rounds` equals the number of slashable misses recorded for the node.

## 4. What step 1 found

The two events carry the version, checked against the contract rather than against itself: a test
samples `isEligibleAt` at every moment a round could open, across a join, a removal, and a rejoin,
then rebuilds the node's intervals from the **recorded logs alone** and requires them to agree. Its
first draft asserted `deactivated < deactivated` — trivially false, so it passed while checking
nothing. Emitting the pre-increment version on deactivation now fails it.

Intervals live in their own table, because a registration emits the activation before the
registration itself, so the node's row does not yet exist when its first interval opens.

Closing an interval is where a re-index goes wrong. "Close whichever interval is still open" would, on
a replay after a rejoin, close the *new* interval with the *old* deactivation. The query instead
closes the latest interval that began before the deactivation. Run against real Postgres, a join at
v2, removal at v4, and rejoin at v6 produce `[2,4) MANUAL` and `[6, open)`, and replaying the whole
history leaves them identical. The naive query, tried for contrast, was rejected by the table's own
check that an interval cannot close before it opened.

An unmatched deactivation — the activation was never indexed, as for an indexer started after the
node joined — records nothing. That period has no interval, so the node is not judged for it:
unknown eligibility must never become a miss.

## 5. Build order

1. The event change, the regenerated ABI, the layout check confirming storage did not move, and the
   indexer migration recording active intervals.
2. Miss detection in the aggregator, with §2.2's exclusions and §2.3's streak, as pure functions tested
   against constructed histories before any wiring.
3. Execution through the existing slashing executor, and an end-to-end test on a real chain: a node that
   misses, a node that misses three times, a node deactivated by an admin, and a round nobody submits to.
4. The Nodes page corrected, and ORC-1 moved to the decided table.

**Upgrade path, for the record:** on a deployed system, rounds opened before the upgrade have no
version history in events and would not be judged. Nothing is deployed, so there is nothing to lose.
